# Работа с IndexBudget

Инструкция действует во всём репозитории. Учитывай указания пользователя и инструкции
конкретного каталога. Обсуждения и документация ведутся на русском, имена в коде на английском.

## С чего начать

- Разработка: прочитай [соглашения](ai/development.md), затем нужные разделы
  [архитектуры](ai/architecture.md), [контрактов](ai/contracts.md) и спецификации.
- Ревью: следуй [порядку проверки](ai/review.md). Не меняй код, ветку и метаданные PR,
  не запускай тесты. Если пользователь просит замечания только в чате, не публикуй их.
- Документация: сверяй описание со спецификацией и связанной issue. Различай готовое
  поведение и планы.

## Требования и устройство проекта

[Спецификация v0.2](IndexBudget-spec-v0.2.md) определяет поведение, формулы, лимиты
и критерии приёмки. [План #2](https://github.com/ITMO-DevDays-2026-IndexBudget/IndexBudget/issues/2)
и конкретная issue задают объём работы, владельцев и зависимости.
[PoC #22](https://github.com/ITMO-DevDays-2026-IndexBudget/IndexBudget/issues/22) и
[MVP #21](https://github.com/ITMO-DevDays-2026-IndexBudget/IndexBudget/issues/21) имеют
отдельные критерии. [Папка ai/](ai/README.md) помогает ориентироваться в проекте.

Если документы противоречат друг другу, укажи расхождение. При изменении поведения
обновляй код, спецификацию, контракты и примеры вместе. Обычные решения реализации
принимай самостоятельно.

CLI поддерживает `analyze`, `analyze-series`, снимки статистики и импорт workload.
`AnalysisPipeline` связывает SQL resolution, JDBC-каталог, кандидаты/refill, HypoPG,
метрики, поиск и экспорт HTML/JSON/SQL. Анализирует SELECT и ограниченные UPDATE/DELETE
без выполнения DML. INSERT используется только отдельным физическим benchmark.
Веб-демо вызывает CLI на фиксированных датасетах.

Команды находятся в [README](README.md), точные интерфейсы в
[docs/contracts.md](docs/contracts.md). Перед изменениями посмотри текущую реализацию.
Готовность подтверждай результатами проверок.

Стек: Kotlin/JVM, JDK 25 LTS, Gradle Kotlin DSL, Spring Boot с
`WebApplicationType.NONE`, Jackson, PostgreSQL JDBC, PostgreSQL 16 и HypoPG.
HTTP-обёртка демо отделена от ядра CLI. [Границы компонентов](ai/architecture.md)
описывают ответственность пакетов; отдельных Gradle-модулей для них не требуется.

## Инварианты

- Один набор индексов даёт один полный вектор costs для общих SQL. Частоты 1–3 профилей
  применяются к нему в памяти. Метрики, бюджеты и компаратор реализованы в domain.
- Оценивай комбинацию целиком. Частичный вектор не обновляет результат;
  одиночные выигрыши нельзя складывать.
- Ограничивай колонки до генерации пар. Сохраняй полный SQL и каталог,
  показывай отсечения, неизвестные оценки и причины остановки.
- Используй одну выделенную JDBC-сессию, общий RunContext и счётчики.
  Освобождай ресурсы при любом завершении. Сохранённый результат должен
  экспортироваться без нового EXPLAIN даже после потери сессии.
- Обычный анализ не создаёт реальные индексы, не вызывает ANALYZE/EXPLAIN ANALYZE
  и не подстраивает планировщик ради результата. Физические замеры выполняются отдельно.
- Различай planner cost, реальное время, оценку и факт размера, write proxy.
  Изменение cost не доказывает ускорение, SLA или глобальный оптимум.
- `best_robust` и `best_mean` относятся к одному исследованному пулу.
  JSON/HTML/SQL должны описывать один запуск и выбранный набор, без секретов.

## Проверки и результат работы

При разработке запускай проверки изменённого поведения. Для документации достаточно
сверки смысла, ссылок и diff. При ревью тесты не запускаются; готовые CI-логи читать можно.

Не стирай чужие изменения и не включай несвязанные файлы. В ответе укажи изменения,
выполненные проверки и то, что осталось непроверенным, с причиной.

## Общая БД и секреты

Перед изменением стенда прочитай [deploy/db/README.md](deploy/db/README.md).
БД обновляется через server-pull; CI не имеет SSH-доступа. Не сохраняй пароли, ключи,
адрес стенда и дампы в Git. Не меняй чужие сервисы WSL, не удаляй общий volume
и не запускай глобальный Docker prune. Persistence test запускается только на одноразовом CI runner.

# Документы для разработки и ревью

Начальная инструкция для агента — [AGENTS.md в корне](../AGENTS.md). В этой папке хранится контекст проекта, который помогает реализовывать и проверять [спецификацию v0.2](../IndexBudget-spec-v0.2.md).

| Документ | Когда читать |
| --- | --- |
| [Архитектура](architecture.md) | Перед изменением границ компонентов, потока данных и владения ресурсами. |
| [Контракты](contracts.md) | При изменении CLI/JSON, моделей между модулями, метрик, ошибок или артефактов. |
| [Разработка](development.md) | Порядок работы по issue, соглашения Kotlin, ошибки, ресурсы и проверки. |
| [Ревью](review.md) | Статическая проверка PR и публикация замечаний к строкам; без запуска тестов. |

Нормативные формулы, алгоритм и лимиты находятся в спецификации; эти документы дают навигацию и объясняют обязанности компонентов. Расписание, назначения и зависимости ведутся в [плане #2](https://github.com/ITMO-DevDays-2026-IndexBudget/IndexBudget/issues/2). Ранний [PoC #22](https://github.com/ITMO-DevDays-2026-IndexBudget/IndexBudget/issues/22) не означает завершение [MVP #21](https://github.com/ITMO-DevDays-2026-IndexBudget/IndexBudget/issues/21).

На момент добавления документов реализация ещё не создана. Целевая структура и CLI-контракт не являются инструкцией запуска существующего приложения; фактические команды сборки и demo должны появиться в корневом README вместе с каркасом.

При изменении публичного поведения синхронизируй спецификацию, примеры и затронутые документы. Не создавай отдельные HTTP/OpenAPI-правила для проекта без HTTP API: его внешние контракты — CLI, входной JSON и выходные файлы.
